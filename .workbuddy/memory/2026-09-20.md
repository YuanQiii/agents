### 本轮踩的两个坑（都值得记住）

**坑 A：git 钩子里的裸 `pnpm` 在 Git-Bash 下会崩。** pre-commit 内容是 `pnpm typecheck && ...`，
而本机 `pnpm`（无扩展名的 shim）在 MSYS 下会拼出被改写的路径而抛错 → 钩子第一步即失败。
`pnpm.cmd` 与 corepack 入口都正常，但钩子用的是裸 `pnpm`，改不了。
**修法（不动仓库、不用 `--no-verify`）**：造一个垫片目录前置到 PATH，再提交——
```sh
printf '#!/bin/sh\nexec node "C:/nvm4w/nodejs/node_modules/corepack/dist/pnpm.js" "$@"\n' > $SHIM/pnpm
chmod +x $SHIM/pnpm
PATH="$SHIM:$PATH" git commit ...
```
这是**让环境能按原意跑钩子**，不是绕过它。

**坑 B：带 pathspec 的 `git commit -- <paths>` 会重置索引里其他文件。**
本仓库 pre-commit 末步是 `git diff --exit-code`（要求工作区与索引一致），于是分主题提交时：
先 `git add -A` 再 `git commit -- 文件子集` → git 把索引里**其余**文件重置回 HEAD → 钩子判定工作区不干净 → 提交被拒
（且 HEAD 不动，容易误以为提交成功）。
**修法**：先 `git reset`，然后「**按组暂存 + 不带 pathspec**」逐个提交——
只要**已跟踪且被修改**的文件全部进第一个提交，其余都是未跟踪文件（对 `git diff` 不可见），后续提交就不会再触发这个矛盾。

### 3. 一次 `.git` 事故：本地仓库元数据被清空（已完整恢复）

第一次尝试建本地分支时：`git checkout -b` / `git switch -c` **只把 HEAD 指向新分支名、不写 refs/heads/<新分支>**，
于是新分支成了「未出生分支」——`git rev-parse HEAD` 报 `Needed a single revision`，commit 变成把全部文件当新文件的初始提交，
push 报 `src refspec ... does not match any`。紧接着一次 `git checkout -f main` 之后，**`.git` 目录整个变空**（只剩空目录），历史全无。

**对照实验**：在 `$TEMP` 新建仓库里同样的 `git switch -c` **完全正常** → 是**本工作区 `.git` 的问题**，不是 git 的。

**恢复**（工作区文件完好，且都已推送，故零内容损失）：
`git init -b main` → `git remote add origin <https>` → `git fetch origin main` → `git update-ref refs/heads/main FETCH_HEAD`
→ `git reset --mixed HEAD` → `git branch --set-upstream-to=origin/main main`。校验：HEAD `4744090`、`git status` **0 差异**。

**教训**：在 `.git` 可疑的环境里，**不要建本地分支**，远程分支一律走 GitHub API；并且**每次提交后立刻推送**，
这样即使本地元数据再被清掉，也能从远程完整恢复。已写进用户级 MEMORY。
