### 本轮踩的两个坑（都值得记住）

**坑 A：git 钩子里的裸 `pnpm` 在 Git-Bash 下会崩。** pre-commit 内容是 `pnpm typecheck && ...`，
而本机 `pnpm`（无扩展名的 shim）在 MSYS 下会拼出被改写的路径而抛错 → 钩子第一步即失败。
`pnpm.cmd` 与 corepack 入口都正常，但钩子用的是裸 `pnpm`，改不了。
**修法（不动仓库、不用 `--no-verify`）**：造一个垫片目录前置到 PATH，再提交——
```sh
printf '#!/bin/sh\nexec node "C:/nvm4w/nodejs/node_modules/corepack/dist/pnpm.js" "$@"\n' > $SHIM/pnpm
chmod +x $SHIM/pnpm
PATH="$SHIM:$PATH" git commit ...
```
这是**让环境能按原意跑钩子**，不是绕过它。

**坑 B：带 pathspec 的 `git commit -- <paths>` 会重置索引里其他文件。**
本仓库 pre-commit 末步是 `git diff --exit-code`（要求工作区与索引一致），于是分主题提交时：
先 `git add -A` 再 `git commit -- 文件子集` → git 把索引里**其余**文件重置回 HEAD → 钩子判定工作区不干净 → 提交被拒
（且 HEAD 不动，容易误以为提交成功）。
**修法**：先 `git reset`，然后「**按组暂存 + 不带 pathspec**」逐个提交——
只要**已跟踪且被修改**的文件全部进第一个提交，其余都是未跟踪文件（对 `git diff` 不可见），后续提交就不会再触发这个矛盾。
